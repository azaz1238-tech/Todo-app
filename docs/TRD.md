# TRD - Todo 앱 기술 명세 (초안)

> 출처: docs/PRD.md, CLAUDE.md
> 상태: 초안 (검토 전)
> TRD = 기술 요구 문서. "무엇을 만들까"는 PRD, "어떤 기술로 어떻게 만들까"는 이 문서에 적는다.

## 1. 기술 스택과 선택 이유

| 기술 | 역할 | 고른 이유 (한 줄) |
|------|------|-------------------|
| Next.js 15 (App Router) | 화면 + API 서버 | 화면과 API를 한 프로젝트 안에서 같이 만들 수 있어서, 서버를 따로 세우지 않아도 된다. |
| React 19 (Next.js에 포함) | 화면 구성 | 체크박스를 누르면 화면이 바로 바뀌는 것처럼, 데이터가 바뀌면 화면을 자동으로 다시 그려 준다. |
| TypeScript (strict) | 개발 언어 | 변수에 "이건 문자열, 이건 true/false" 같은 타입을 적어 두면 실수를 실행 전에 잡아 준다. (any 타입은 쓰지 않는다) |
| Tailwind CSS | 화면 꾸미기 | 별도 CSS 파일 없이 화면 코드 옆에서 바로 스타일을 적을 수 있어 작은 앱에 빠르다. |
| MySQL | 데이터 영구 저장 (DB) | 서버를 껐다 켜도 데이터가 남아야 해서(F-05) DB가 필요하고, MySQL은 널리 쓰여서 자료가 많고 표(테이블) 형태라 할 일 목록에 잘 맞는다. |
| Drizzle ORM | 코드로 DB 다루기 | SQL을 몰라도 TypeScript 코드로 DB를 읽고 쓸 수 있고, 타입 검사도 이어진다. |
| Zod | 입력값 검사 | "제목 필수, 1~100자"(F-01) 같은 규칙을 한곳에 적어 두고 들어온 값을 검사한다. |
| Jest | 테스트 실행 | "이 함수에 이걸 넣으면 이게 나와야 한다"를 코드로 적어 두고 자동으로 확인할 수 있다. |
| React Testing Library | 화면 테스트 | 사용자가 실제로 하는 것처럼 "입력하고 버튼 누르기"를 흉내 내서 화면을 검사할 수 있다. |

## 3. 버전별 데이터 저장 방식

| 버전 | 저장 위치 | 새로고침 | 서버 재시작 |
|------|-----------|----------|-------------|
| v0.1 | 브라우저 메모리 | 사라짐 | - |
| v0.2 | 서버 메모리 | 유지 | 사라짐 |
| v0.3 | DB (MySQL) | 유지 | 유지 |

- 4장 흐름은 **v0.3 기준**이다. v0.1~v0.2는 5~6단계의 저장 위치만 다르다.
- 필터와 수정(v0.4), 배포(v1.0)는 해당 버전을 시작할 때 이 문서에 추가한다.

## 4. 흐름: 버튼을 누른 뒤 DB에 저장되기까지 (할 일 추가, F-01)

1. **입력과 클릭**: 사용자가 제목을 입력하고 "추가" 버튼을 누른다. (src/components/)
2. **화면에서 1차 확인**: 제목의 앞뒤 공백을 지운 뒤 비었거나 100자를 넘으면 서버에 보내지 않고 안내 문구를 보여준다.
3. **서버로 요청**: 통과하면 브라우저가 서버 API에 "이 제목으로 할 일을 만들어 달라"고 요청한다. (app/ 의 API 라우트)
4. **서버에서 2차 확인**: 서버가 Zod로 제목 규칙(앞뒤 공백을 지운 뒤 필수, 1~100자)을 다시 검사한다. 화면 검사는 우회될 수 있어서 서버에서도 반드시 확인한다. 실패하면 오류 응답을 보내고 끝낸다.
5. **DB 저장 명령**: 통과하면 서버 로직(src/lib/)이 Drizzle로 새 할 일 한 줄을 만들어 달라고 DB에 명령한다. id와 생성 시각이 함께 기록된다.
6. **DB에 저장**: MySQL이 데이터를 기록한다. 이 시점부터 새로고침이나 서버 재시작에도 데이터가 남는다.
7. **응답**: 서버가 저장된 할 일(id, 제목, 완료 여부, 생성 시각)을 브라우저로 돌려준다.
8. **화면 갱신**: 화면이 응답을 받아 목록 맨 위(최신순)에 새 할 일을 보여주고 입력칸을 비운다.

- 완료 전환(F-03)과 삭제(F-04)도 같은 길을 따른다. 3단계의 요청 내용과 5단계의 DB 명령(수정/삭제)만 다르다.
- 목록 보기(F-02)는 반대 방향이다. 화면이 서버에 요청 → 서버가 DB에서 읽기 → 최신순 정렬 → 응답 → 화면에 표시.
- 요청의 주소, 응답, 오류 형식은 docs/API_SPEC.md, 테이블 구조는 docs/DATA_MODEL.md에 정의한다.

## 5. 지켜야 할 기술 규칙 (CLAUDE.md 기준)
- any 타입 금지, TypeScript strict 유지
- 명세에 없는 기능은 임의로 추가하지 않고, 진행 중인 버전 범위를 넘어 미리 구현하지 않는다.
- 한 번에 한 기능만 작업하고, 끝나면 무엇을 바꿨는지 요약한다.
- 테스트를 삭제하거나 skip하지 않는다. 실패하면 테스트가 아니라 구현을 고친다.
- console.log는 디버깅 후 제거한다.
- 주석은 한국어로 짧게 쓴다.
