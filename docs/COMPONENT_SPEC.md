# COMPONENT_SPEC - 화면 부품 명세 (초안)

> 출처: docs/PRD.md, docs/API_SPEC.md, docs/DATA_MODEL.md
> 상태: 초안 (검토 전)
> 컴포넌트 = 화면을 이루는 부품. 파일은 src/components/ 에 두고, 페이지는 app/page.tsx에서 TodoPage를 불러 쓴다.

## 1. 컴포넌트 트리

```
TodoPage
├─ TodoForm      : 입력창 + 추가 버튼
├─ TodoFilter    : 전체 / 진행 중 / 완료 (v0.4, 지금은 만들지 않음)
└─ TodoList
   └─ TodoItem   : 체크박스 + 제목 + 삭제 버튼
```

| 컴포넌트 | 하는 일 | 기능 | 데이터를 갖나 |
|----------|---------|------|---------------|
| TodoPage | 할 일 목록, 로딩, 에러 상태를 갖고 API를 호출한다. 아래 부품들을 배치한다 | F-02, F-05 | 예 (유일) |
| TodoForm | 입력칸 값을 관리하고 1차 검사를 한다 | F-01 | 입력값만 |
| TodoList | 받은 목록을 순서대로 그린다. 빈 목록이면 안내 문구를 보여준다 | F-02 | 아니오 |
| TodoItem | 할 일 한 줄을 그린다 | F-03, F-04 | 아니오 |

- 데이터를 TodoPage 한 곳만 갖게 해서 "데이터가 어디서 바뀌는지" 헷갈리지 않게 한다.
- TodoFilter는 v0.4에서 정의한다. 지금은 트리에 자리만 표시하고 props도 정하지 않는다.

### 요소 이름 (테스트에서 화면 요소를 찾는 기준)

| 요소 | 이름 |
|------|------|
| 제목 입력칸 | label "할 일 제목" |
| 추가 버튼 | "추가" |
| 체크박스 | 그 항목의 제목 (제목을 label로 연결) |
| 삭제 버튼 | "삭제" |

## 2. Props 타입

`Todo` 타입은 docs/DATA_MODEL.md와 같다.

### TodoPage
- props 없음 (최상위 부품)

### TodoForm

| Prop | 타입 | 설명 |
|------|------|------|
| onAdd | (title: string) => Promise&lt;void&gt; | 1차 검사를 통과한 제목을 부모에 넘긴다. 성공하면 resolve, 실패하면 reject. 폼은 resolve됐을 때만 입력칸을 비운다 |
| disabled | boolean | 저장 중이면 true. 추가 버튼을 잠근다 |
| errorMessage | string \| null | 추가 실패 시 입력칸 아래에 보여줄 문구 |

### TodoList

| Prop | 타입 | 설명 |
|------|------|------|
| todos | Todo[] | 서버가 최신순으로 정렬해 준 목록 (화면에서 다시 정렬하지 않는다) |
| onToggle | (id: number, completed: boolean) => void | 체크박스 변경을 부모에 전달 |
| onDelete | (id: number) => void | 삭제 클릭을 부모에 전달 |

### TodoItem

| Prop | 타입 | 설명 |
|------|------|------|
| todo | Todo | 할 일 한 개 |
| onToggle | (id: number, completed: boolean) => void | TodoList가 받은 것을 그대로 전달 |
| onDelete | (id: number) => void | TodoList가 받은 것을 그대로 전달 |

## 3. 사용자 동작과 결과

| 동작 | 화면 결과 | 호출하는 API |
|------|-----------|--------------|
| 페이지 열기, 새로고침 (F-02, F-05) | 저장된 목록이 최신순으로 보임 | GET /api/todos |
| 제목 입력 후 추가 클릭 (F-01) | 목록 맨 위에 새 항목이 생기고 입력칸이 비워짐 | POST /api/todos |
| 빈 제목, 공백만, 100자 초과로 추가 | 요청을 보내지 않고 입력칸 아래에 안내 문구 | 없음 (1차 검사) |
| 체크박스 클릭 (F-03) | 완료 항목은 제목에 취소선이 생기고, 다시 누르면 원래대로 | PATCH /api/todos/:id |
| 삭제 클릭 (F-04) | 해당 항목이 목록에서 사라짐 | DELETE /api/todos/:id |

- 서버가 성공을 돌려준 뒤에 화면을 바꾼다. 그래야 화면과 저장된 데이터가 어긋나지 않는다.
- v0.1은 서버가 없으므로 TodoPage가 새 항목을 목록 맨 앞에 넣어 최신순을 맞춘다. v0.2부터는 서버가 정렬한 순서를 그대로 쓴다.
- 위 표의 "호출하는 API" 열은 v0.2부터 해당한다. v0.1은 브라우저 메모리만 바꾼다.
- 1차 검사: 제목 앞뒤 공백을 지운 뒤 비었거나 100자를 넘으면 막는다. (docs/TRD.md 4장)
- 100자는 서버와 같게 글자 수로 센다. 이모지도 한 글자다. (docs/API_SPEC.md 2장) 구현할 때 `title.length`가 아니라 `[...title].length`를 쓴다.
- 완료 항목도 목록 순서는 그대로 두고 취소선만 바꾼다. 위치를 옮기지 않는다.
- 삭제는 확인 창 없이 바로 처리한다.

## 4. 상태별 화면과 문구

| 상태 | 언제 | 화면 | 문구 |
|------|------|------|------|
| 로딩 | 첫 목록 조회 중 | 목록 자리에 문구 | "불러오는 중..." |
| 빈 목록 | 할 일이 0개 | 목록 자리에 문구 | "할 일이 없습니다. 위에서 추가해 보세요." |
| 목록 조회 실패 | GET 실패 | 목록 자리에 문구 + [다시 시도] 버튼 | "목록을 불러오지 못했습니다" |
| 추가 실패 | POST 실패 (400, 500) | 입력칸 아래에 문구. 입력값은 그대로 둠 | 응답의 error.message |
| 전환, 삭제 실패 | PATCH, DELETE 실패 | 목록 위쪽에 한 줄. 항목 상태는 그대로 | 응답의 error.message |
| 저장 중 | 추가 요청이 오가는 동안 | 추가 버튼 비활성화 (중복 클릭 방지) | 문구 없음 |

- 서버에서 온 에러 문구는 docs/API_SPEC.md의 `error.message`를 그대로 쓴다. 1차 검사 문구도 같은 문장을 쓴다. ("제목은 필수입니다", "제목은 100자 이하여야 합니다")
- 전환이나 삭제에서 404(NOT_FOUND)가 오면 이미 없는 할 일이므로 목록에서 그 항목을 지우고 "할 일을 찾을 수 없습니다"를 한 줄로 보여준다. 그 밖의 에러는 항목을 그대로 둔다.
- 에러 문구는 사용자가 다음 동작(다시 입력, 다시 시도)을 하면 사라진다.
- 네트워크가 끊겨 서버 응답이 아예 없으면 "서버에 연결할 수 없습니다"를 같은 자리에 보여준다.
- v0.1(브라우저 메모리)은 서버 요청이 없어서 로딩과 서버 에러 상태가 없다. v0.2부터 나타난다.

## 5. 아직 정하지 않은 것
- 삭제 확인 창 (지금은 "없이 바로 삭제"로 가정. PRD 열린 질문)
- 저장 중에 체크박스와 삭제 버튼도 잠글지 (지금은 추가 버튼만 잠금)
- TodoFilter의 props와 동작 → v0.4 시작 시 정의

## 6. 결정한 것
- 완료 항목도 목록 위치를 그대로 둔다. 취소선만 바꾼다. (PRD 7장의 열린 질문에 대한 결정)
- 전환, 삭제 때 404가 오면 그 항목을 목록에서 지운다. (4장)
